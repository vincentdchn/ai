# Domain documentation seed

Use this optional seed only for requested domain-documentation setup. Replace examples with the repository's verified sources before writing guidance. Do not create a glossary or decision-record hierarchy merely to fill this template.

## Sources to identify

- The existing glossary or product terminology reference, if any.
- Relevant architecture decision records and their actual locations, if any.
- Any documented mapping between product contexts and their sources.

`CONTEXT.md`, `CONTEXT-MAP.md`, and `docs/adr/` are possible layouts, not requirements. Repository structure alone does not establish business context boundaries. If a source is absent, continue the requested work without inventing a mandatory setup dependency.

## Consumer guidance to adapt

Use the canonical terminology when naming product concepts. Read decisions relevant to the task and surface a real conflict rather than silently reversing an agreed decision.

Link to existing sources instead of copying their definitions. Report an unresolved terminology gap only when it affects the requested work. Propose new documentation when needed, then obtain approval before creating it.
